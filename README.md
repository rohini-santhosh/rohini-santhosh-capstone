# Narra — a UX research library

Narra is a small library of hand-off-ready UX research reports: real sources,
observations, insights, pain points, behavior patterns, personas,
contradictions, a journey map, flows, a summary, and product direction — all
traceable back to a real URL.

**There is no API key, login, or backend AI call anywhere in this app.** The
deployed server only does two things: serve pre-generated report files, and
queue topic suggestions to a local file. New reports are generated by asking
Claude (in a Claude Code session on this repo) to research a topic — see
[`RESEARCH_METHOD.md`](./RESEARCH_METHOD.md) for the exact process and output
schema Claude follows every time, so reports stay consistent regardless of
which session made them.

> The `agent.py` / `WORKFLOW.md` described in `Working agent.md` / `Agent.md`
> was an earlier, different concept (a local CLI tool calling the Claude API
> directly). This app superseded that approach — no live API calls, ever.

## Project layout

```
server/
  index.js       Express app — static site + 3 endpoints, no auth, no API key
  requests.js     Reads/writes server/data/requests.json (topic suggestion queue)
  rateLimit.js     Generic in-memory per-IP rate limiter
public/
  index.html, styles.css, app.js   The Narra frontend
  research/
    index.json                     List of published reports (slug, topic, scope, createdAt)
    <slug>.json                    One full report per file
RESEARCH_METHOD.md                 The process + schema Claude follows to generate a report
```

## API surface (no auth, no key)

- `GET /api/research` — list of published reports (from `public/research/index.json`)
- `GET /api/research/:slug` — one report's full JSON (from `public/research/<slug>.json`)
- `POST /api/requests` `{ topic, scope? }` — queues a topic suggestion to
  `server/data/requests.json` (rate-limited per IP, 10/hour)
- `GET /api/requests` — read the current queue (plain JSON, no auth — see
  "Publishing a new report" below)

## Local development

Requires Node.js 18+. No environment variables needed.

```bash
npm install
npm start
```

Open http://localhost:3000 — browse the published reports, or suggest a new
topic (it just queues, nothing runs automatically).

## Publishing a new report

1. Ask Claude, in a session on this repo, to research a topic (optionally
   pulling one from `server/data/requests.json`).
2. Claude follows [`RESEARCH_METHOD.md`](./RESEARCH_METHOD.md): gathers real
   sources via web search, extracts observations, and writes the full report
   as `public/research/<slug>.json`.
3. Claude adds an entry to `public/research/index.json`.
4. No server restart needed — both are static files. Commit and push (or
   redeploy) to publish.

## Deploying to Railway

1. Push this repo to GitHub.
2. In Railway: **New Project → Deploy from GitHub repo**.
3. Railway auto-detects Node via Nixpacks and runs `npm start` (see
   `railway.json` / `Procfile`) — no Dockerfile, no environment variables,
   no secrets to configure.
4. Deploy. Railway assigns a public URL; the server already binds to
   `process.env.PORT`.

That's the whole deploy — nothing else to set up.
